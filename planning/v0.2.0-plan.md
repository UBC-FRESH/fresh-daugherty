# fresh-daugherty master plan — v0.2.0 (scope expansion)

Expansion of the reproduced Daugherty (1991) benchmark with four modelling
extensions (E1–E4) and one dissemination extension (E5), agreed with
co-author J. Fuchs (BOKU) 2026-09. The v0.1.x core reproduction (thesis grid:
18 landbases × 4 constant discount rates × 6 flow policies, 432 cells) stays
intact and unchanged; all extensions are additive and are evaluated against
the same divergence metric (`eq:metric`), the same occurrence criterion (5%
mean-divergence tolerance), and the same objective-gap diagnostic (the
genuineness test that separates real inconsistency from alternate optima).

The cross-cutting evaluation question for E1–E4 is identical in every case:
**does the variant mitigate, or eliminate, dynamic inconsistency?** — measured
as occurrence share, mean magnitude, and gap-diagnostic outcome, reported
against the matched core-grid control cells.

Manuscript work lives in the separate Overleaf-linked repo
(`ubc-fresh/fresh_daugherty_manuscript`, local clone
`~/projects/fresh_daugherty_manuscript`); the paper-side expansion plan is
`planning/manuscript-expansion-plan.md` there. This repo remains the sole
source of modelling code, experiment records, and (new) the curated
supplementary material (E5).

## E1 (P9) — Time-varying discount-rate shapes

Current state: the LP objective applies a constant per-period discount factor
`delta = (1+i)^-1`, `i ∈ {0, 2, 4, 6}%` (thesis replication), implemented as
scalar discounting in `lp.py`.

Extension: parameterize a **per-period discount-rate path** `r_t` (equivalently
a factor path `delta_t = prod_{s<=t} (1+r_s)^-1`) and test non-constant shapes:

- `constant` (existing; control; the thesis's four rates);
- `linear`: `r_t = max(r0 - s*(t-1), r_floor)` — a linearly declining rate,
  e.g. from `r0 ∈ {4%, 6%}` down to a floor of 0% (or a small positive floor)
  at or before the horizon;
- `inverse-j`: constant `r0` for the first `k` periods (`k ∈ {1, 2}`, i.e. the
  first ~10–20 years), then exponential decay `r_t = r0 * exp(-λ (t-k))` for
  `t > k`, with λ chosen to roughly halve the rate per period (exact parameter
  set fixed in the experiment config at implementation time).

Design decisions:

- The discount path is an **instance/config record** (typed, provenance-
  stamped like the rest of the case-study data), not a hard-coded formula in
  the LP builder; `lp.py` consumes a per-period factor vector.
- Grid accounting: keep the core 432-cell grid untouched; add the new paths as
  additional tracked grids. Proposed: 2 linear + 2 inverse-j paths × 18
  landbases × 6 policies = 432 new cells per path family (exact count fixed in
  the P9 issue body; the runner is embarrassingly parallel so cost is not a
  constraint).
- Interpretation subtlety to carry into the paper: a declining instantaneous
  rate is hyperbolic-style discounting, which introduces a *preference-level*
  time inconsistency of the planner's own (Strotz-type) on top of the
  structural (flow-constraint) inconsistency. The experiment therefore
  separates two questions: (a) does heavier far-future weighting reduce the
  front-loading that drives the structural phenomenon; (b) does the added
  preference drift itself show up in the gap diagnostic? Report both.

Tasks (child issues):

- **P9.1** Discount-path records + config: typed, provenance-stamped per-period
  rate-path records (`constant` / `linear` / `inverse-j` families, with
  parameters); config parsing at the boundary.
  - Subtasks: path schema; parameter set fixed (2 linear + 2 inverse-j paths);
    validation tests.
- **P9.2** LP builder support for per-period discount-factor vectors: `lp.py`
  consumes a factor path instead of a scalar; objective coefficients wired per
  period; constant path reproduced bit-identically (regression check vs the
  core grid).
- **P9.3** Discount-shape experiment grids: tracked entry point; new paths ×
  18 landbases × 6 policies; per-cell records with full provenance.
- **P9.4** Analysis + closeout: occurrence/magnitude/gap-diagnostic tables vs
  the constant-rate control; the preference-level (Strotz) vs structural
  inconsistency separation written up for the manuscript.

Acceptance: new discount-path records + LP builder support; per-path grids run
through the tracked experiment entry point; occurrence/magnitude/gap-diagnostic
tables vs the constant-rate control; tests covering path generation and LP
coefficient wiring.

## E2 (P10) — Max-harvest-cap even-flow search

Swap the NDY link for a simple **cap** `H_t <= cap` (all periods), then
iteratively re-solve, tightening the cap, until the harvest trajectory
satisfies an even-flow criterion.

Components to build:

- **Cap constraint form** in the LP builder (a single bound row per period;
  mechanically the simplest of the extensions).
- **Even-flow pattern metric** (new typed module, e.g. `evenflow.py`):
  composite score over the trajectory with configurable thresholds —
  (a) trend: OLS slope of `H_t` on `t`, bounded in magnitude (default: |slope|
  no more than a small fraction of the mean per period);
  (b) fluctuation: max period-over-period relative change `|ΔH_t| / H̄` bounded;
  (c) dispersion: coefficient of variation (SD/mean) bounded.
  Defaults fixed in config at implementation time; all three components and
  their thresholds recorded in the cell record.
- **Search driver**: bisection on `cap` between a feasible-high start (e.g.
  the unconstrained period-1 harvest) and infeasibility, stopping at the
  loosest cap whose trajectory meets the even-flow thresholds (or declaring
  failure after a bounded iteration count). Monotone tightening keeps
  bisection valid.

Key design decision (flagged during scoping): evenness is scored on **both**
the open-loop projection and the realized sequential-replanning trajectory;
the **realized** trajectory is the primary criterion (the honest-trajectory
view: a cap tuned to look even only in the projection but abandoned under
replanning is exactly the pathology under study). The secondary, scientifically
interesting output: because the cap removes the per-period flow *link* (the
operative between-period coupling), does a cap calibrated for realized
evenness turn out to be dynamically consistent? This connects directly to the
paper's remedies discussion (automated allowable-cut calibration) and to the
allowable-cut-effect literature already cited.

Tasks (child issues):

- **P10.1** Cap constraint form in the LP builder (`H_t <= cap` rows).
  - Subtasks: row geometry; config flag; unit tests vs an unconstrained solve.
- **P10.2** Even-flow pattern metric module (typed; slope, max relative
  fluctuation, coefficient of variation; configurable thresholds with recorded
  defaults).
  - Subtasks: metric schema; threshold defaults fixed; unit tests on synthetic
    trajectories (level, trending, oscillating).
- **P10.3** Bisection search driver: feasible-high start, monotone tightening,
  bounded iterations, infeasibility handling; per-cell records (calibrated cap,
  metric components, iteration history).
- **P10.4** Grid + analysis: cap-search cells scored on open-loop and realized
  trajectories; consistency of cap-calibrated plans (gap diagnostic); write-up
  of the allowable-cut-calibration connection for the manuscript.

Acceptance: cap form + evenness metric + bisection driver; per-cell records
include the calibrated cap, the metric components, iteration history, and the
standard inconsistency scores; tests for metric correctness, bisection
convergence, and infeasibility handling.

## E3 (P11) — Value-denominated flow constraints

Reformulate the bounded-deviation link in **dollars** instead of volume:
constrain period net revenue `R_t = Σ (net price) × (harvested area/volume)`
(**undiscounted**) with the same policy forms (NDY, bounded decline, symmetric
bounded deviation now on `$`).

Design decisions:

- Implementation is a **coefficient change in the flow rows**, not a structural
  rebuild: revenue coefficients are already computed for the objective.
  Parameterize the flow-row denominator (`volume | revenue`) in the LP config.
- Divergence scoring: report `δ_t` on **both** the volume and the revenue
  trajectories for every cell, so revenue-constrained cells remain comparable
  with the volume-constrained core grid.
- Hypothesis (ties to `planning/null-discount-neg-valued-basis.md`): under a
  volume NDY, negatively-valued CM-CE area can enter the basis as
  constraint-filler because it *adds* volume; under a revenue NDY it *subtracts*
  from `R_t` and can never relax the floor, so the filler channel is
  structurally disabled. If inconsistency persists under value-flow it must
  come through the positive-value strata and the state transition alone; if it
  vanishes, that is strong evidence for the filler-variable channel being the
  operative driver. Either outcome is reportable; the gap diagnostic
  adjudicates genuineness.

Tasks (child issues):

- **P11.1** Flow-row denominator parameterization (`volume | revenue`) in the
  LP builder: revenue coefficients wired into the bounded-deviation rows; the
  volume form reproduced bit-identically (regression check).
- **P11.2** Dual-metric divergence scoring: `δ_t`, mean divergence, occurrence,
  and relative volume change computed on **both** volume and revenue
  trajectories for every cell; metric records extended accordingly.
- **P11.3** Revenue-denominated grid + analysis: matched subset of the core
  grid; filler-channel hypothesis test (CM-CE basis entries under revenue NDY);
  gap-diagnostic evidence; write-up for the manuscript.

Acceptance: denominator parameterization + revenue-denominated policy grid
(matched subset of the core grid, exact scope fixed in the P11 issue body);
dual-metric (volume + revenue) divergence records; tests for row-coefficient
correctness and metric wiring.

## E4 (P12) — Rolling-mean NDY

Replace the pointwise consecutive-period link with a **backwards-facing rolling
mean**: `H_{t+1} >= (1/k) Σ_{i=t-k+1..t} H_i` for window `k ∈ {2, 3}`. Still
linear; a new constraint form in the LP builder.

Key design decision (flagged during scoping): whether the window reaches back
into **realized** past harvests or only within-plan projected values.

- *Within-plan* reading: each replan re-anchors freely (current "fresh
  constraint" institution); the rolling mean merely smooths the reference
  level inside each subproblem.
- *Realized-history* reading: the new subproblem's early periods are floored
  by what actually happened — a different replanning institution, close to the
  carried-flow-history variant already noted in the paper as suppressing the
  phenomenon.

Run **both** readings and report the contrast; this partially tests the
anchoring convention itself, not just the constraint shape. Seeding convention
for `t < k` (partial window vs exogenous seed) fixed in the P12 issue body.

Tasks (child issues):

- **P12.1** Rolling-mean constraint form in the LP builder:
  `H_{t+1} - (1/k) Σ_{i=t-k+1..t} H_i >= 0`, `k ∈ {2, 3}`; seeding convention
  for `t < k` fixed and recorded.
  - Subtasks: row geometry; seeding rule; unit tests vs pointwise NDY.
- **P12.2** Anchoring readings in the replanning simulator: config flag for
  within-plan vs realized-history windows; realized-history reading wires the
  realized past harvests into the new subproblem's early rows.
- **P12.3** Grid + analysis: `k ∈ {2, 3}` × both readings; standard
  inconsistency scoring + gap diagnostic; the anchoring-institution contrast
  written up for the manuscript.

Acceptance: rolling-mean constraint form; both anchoring readings implemented
behind a config flag; grid over `k ∈ {2, 3}` × readings (scope fixed in the
issue body); standard inconsistency scoring; tests for row geometry and
window seeding.

## Cross-cutting requirements (all phases)

- Follow the strict development workflow in `AGENTS.md`: one parent issue and
  one feature branch per phase (issue numbers recorded in ROADMAP.md once
  created); child issues per task; PR to `main` at phase close.
- The core 432-cell grid and its tracked records are **not modified**;
  extensions add new tracked grids/records alongside.
- Every new cell record carries provenance (config hash, code version,
  environment) per the repo's existing reproducibility standard.
- The objective-gap diagnostic runs on every extension cell; metric-only
  divergence without the diagnostic is not reportable as inconsistency.
- Verification per `AGENTS.md`: `ruff check`, `pytest`, `sphinx-build -W`,
  `python -m build`, `twine check`.
- J. Fuchs (BOKU) joins as co-author and will provide detailed review comments
  on the manuscript; modelling-repo planning should treat the four evaluation
  questions (mitigate/eliminate, per extension) as the fixed backbone those
  comments will refine, not redesign.
